# Code layout

- **No comments**, in Rust, TypeScript or Svelte: the why lives here, in `design/`.
- **At most 1,000 lines per file**; small functions with one purpose.
- **`pub(crate)` by default** in Rust; `pub` only across crates of the workspace.
- **Licence**: `MIT OR Apache-2.0`, as cornercase-terminal.
- **The machines check these rules, not the reviewer**: clippy the size of Rust functions, ESLint that of TypeScript, JavaScript and Svelte functions, `scripts/check-rules.mjs` the 1,000 lines and the comments in every language, `unreachable_pub` the `pub(crate)`, jscpd the copies. Each runs in CI, so a rule they cover never waits for a review.

## Small functions

- **The same limits as cornercase-terminal and cornercase-gpui**: `clippy.toml` sets `too-many-lines-threshold = 40`, `too-many-arguments-threshold = 5`, `excessive-nesting-threshold = 4` and `cognitive-complexity-threshold = 10`. `cognitive_complexity` is in `nursery`, so `[workspace.lints.clippy]` turns it on; it also names `excessive_nesting` (in `all`, which is `deny`) and `too_many_lines` (in `pedantic`), the three at `warn` as in cornercase-terminal, which CI's `-D warnings` makes an error. How clippy counts them is in cornercase-terminal's `design/code-layout.md` (Small functions): `self` is an argument, the `impl` and the function's body are levels of nesting, `&&` and `||` add no complexity.
- **ESLint** (`eslint.config.js`, every `.ts`, `.js`, `.mjs` and `.svelte` file, `scripts/` included) sets `max-lines-per-function` 40 (blank lines left out), `complexity` 10 and `max-depth` 3, at `error`. No rule limits a TypeScript function's arguments (`max-params` is off), unlike clippy's 5.
- **The numbers match, the counts do not**, and that is accepted rather than tuned (checked on 2026-11-08 with clippy 1.99.1 and ESLint 10.14):
  - **Lines**: clippy counts the body's lines without the line of the signature and the closing brace; ESLint counts from the signature to the closing brace. So a Rust function holds 40 lines of body and a TypeScript one 38.
  - **Nesting**: clippy counts every block, the `impl` and the function's body included, so 4 leaves two levels inside a method and three in a free function, and a closure's body is one more level. ESLint's `max-depth` counts only the blocks inside the function (`if`, `for`, `while`, `switch`, `try`), three of them in a method or in a free function alike, and starts again at zero in a callback, which is a function of its own.
  - **Complexity**: clippy's is cognitive, ESLint's cyclomatic. ESLint adds 1 for each `if`, loop, `case`, `catch`, ternary, `&&`, `||`, `??`, logical assignment, `?.` and default value; clippy adds nothing for `&&`, `||`, `?` or a closure. A long chain of conditions therefore splits sooner in TypeScript.
  - Rejected: picking other numbers per language so the counts line up. Nobody keeps two sets of numbers in mind, and the point is the same habit on both sides, not the same function.
- **`max-lines-per-function` is off in `**/*.test.ts`**: for ESLint a `describe` callback is a function, and it grows with each `it`. Its Rust counterpart is a `mod tests`, which clippy does not measure. `complexity` and `max-depth` still apply to tests. Rejected: keeping it on and splitting each `describe` into groups of 40 lines, which cuts tests by size rather than by subject.

## `scripts/check-rules.mjs`

- **What it checks**: every file over 1,000 lines, counted as Rust's `lines()` does (a final newline adds no line), and every comment. In `.rs`, `.ts`, `.js` and `.mjs`: `//` and `/* */`, which takes in `///`, `//!` and `/** */`; Rust's block comments nest. In `.svelte` and `.html`: `//` and `/* */` in `<script>`, `/* */` in `<style>` and `<!-- -->` in the markup; an HTML page is read by the same lexer as a Svelte component, since the three comments are the same. In `.css`: `/* */`, the only comment CSS has, outside its strings. A shebang on a file's first line is not a comment. Each failure prints `path:line: reason` and points here. `pnpm lint` runs it after ESLint, so CI needs no step of its own.
- **What it walks**: `crates/`, `src-tauri/src/`, `src-tauri/build.rs`, `src-tauri/plugins/`, `src/`, `scripts/`, `site/` and the root's `*.config.{ts,js,mjs}`, only files with those seven extensions. `scripts/`, `build.rs` and the configs are walked too because the rule in `CLAUDE.md` names no folder that is exempt; `src-tauri/plugins/` so that a plugin's Rust follows the same rules as the app's; `site/` so that the template and the style sheet of the privacy and support pages (`design/releases.md`) carry no comments either. Its markdown is text, not code, and the root's `index.html`, Vite's entry, stays out as before. Data is left out: the JSON fixtures of `crates/core` copy cornercase's `--json` output and may pass 1,000 lines for good reason.
- **Generated code is skipped by path**, in `GENERATED`: any folder named `gen`, `target`, `node_modules` or `dist`, the folders a plugin's build writes (`.build`, Swift's; `.tauri`, the copy of Tauri's Swift package; `autogenerated`, under `permissions/`), and `src/lib/bindings.ts` (tauri-specta's output). It is not a list of exceptions: nobody writes those files, so no rule applies to them.
- **The exceptions, `LONG_FILES` and `COMMENTED_FILES`, are empty and only shrink**, as in cornercase-terminal's `tests/layers.rs`: an entry whose file is gone or follows the rule now fails the script until it is removed, and a file that breaks a rule is fixed, never added. They exist so that a rule added later can start from the files that already break it.
- **No directive is exempt**: `// eslint-disable…`, `// @ts-expect-error`, `/// <reference …>` and `<!-- svelte-ignore … -->` are comments and fail. An ESLint rule is turned off by a block for its files in `eslint.config.js`, with its why here; global types go in `tsconfig`'s `types`. Accepted: an accessibility warning from Svelte is answered by changing the markup, not by ignoring it.
- **A small lexer of its own, not an ESLint plugin nor `typescript`'s scanner**: one tool for Rust, TypeScript and Svelte (ESLint does not read Rust), no dependency, and the same approach as the `tests/layers.rs` of cornercase-terminal and cornercase-gpui. It knows strings, template literals with `${}` nested to any depth, regular expressions, Rust's raw strings (`r#"…"#`), byte strings, and char literals apart from lifetimes (escapes such as `'\u{41}'` and `'\x41'` included). Its one guess is a `/` in TypeScript: a regular expression after an operator, an opening bracket, a `,`, `;`, `{`, `}`, a keyword such as `return`, or at the start; a division after a name, a number, `)`, `]`, `++` or `--`. A wrong guess is fixed by rewriting the line, such as putting the regular expression in a `const`.
- **Swift is not read**: the lexer knows no Swift, so the Swift of a plugin (`src-tauri/plugins/*/ios/`) is written without comments by hand, and a review checks it. The one exception is the first line of `Package.swift`, `// swift-tools-version:…`, which SwiftPM requires and reads. Rejected: teaching the lexer Swift for two small files; a plugin with more Swift is the time to reconsider.
- **What it leaves out**: the layers and imports that `tests/layers.rs` checks in cornercase-terminal (there are no modules yet; it comes with them), `pub(crate)`, which `unreachable_pub` already enforces from the workspace's lints, and comments inside a Svelte markup expression (`{a // b}`), which are rare. Two known limits in Svelte: a `<style lang="scss">` or `lang="less"` would take `//` comments it does not see (there is no preprocessor yet; one that comes in should have that `<style>` read by the TypeScript lexer, or the script reject the `lang`), and a `<!--` inside an attribute's value is taken for a markup comment, in an HTML page too.
- **Its tests**, `scripts/check-rules.test.ts`, call the functions it exports and walk a temporary folder; the script runs its `main` only when Node starts it, through a symlink too. `pnpm check` does not type-check `scripts/` (`tsconfig.json` takes `src/` and `site/src/` only): vitest and ESLint cover it.

## jscpd

- **`.jscpd.json` copies cornercase-terminal's**: clones of 50 tokens or more, failing above 1 % duplication, `maxLines` and `maxSize` far above any file (by default jscpd skips files over 1,000 lines or 100 KB), `.gitignore` honoured. It reads `crates/`, `src-tauri/src/`, `src-tauri/plugins/`, `src/`, `scripts/` and `site/` as Rust, TypeScript and JavaScript (`.mjs` included), and ignores `gen/`, a plugin's `.build/`, `.tauri/` and `permissions/autogenerated/`, and `src/lib/bindings.ts`, as `GENERATED` does. Swift is not among its formats here, like in the script. Like there, it is a ratchet: extract the shared code, do not raise the threshold. It came in with almost no code because a ratchet is cheapest from zero.
- **`.svelte` files are left out**: jscpd has no format for them. Logic that two components would share belongs in a `.ts` module anyway, which it reads.
- **`site/` is read for its TypeScript and JavaScript** since 072, when the landing brought a script of its own (`design/website.md`). Its HTML and CSS are not: adding the `markup` and `css` formats for them would read `src/`'s CSS as well and move the 1 % for no gain.
- **The 1 % is of all the tokens read**, so the same copy weighs less as the code grows: in November 2026, with about 7,400 tokens, a copied block of 60 tokens already failed.
- **Run with `npx -y jscpd@4.3.0`, not from `package.json`**, as in cornercase-terminal: the version is pinned in the command, and the tool and its dependencies stay out of `pnpm-lock.yaml`, Dependabot's pull requests and the app's install. The cost is a download of a few seconds per run.

## CI

- **One job** in `.github/workflows/ci.yml`, on `ubuntu-24.04`, for every pull request, every push to `main` and by hand. A new push to the same branch cancels the run in progress. No iOS or Android builds in this job (macOS runners are expensive); those are checked locally, the Swift of the plugins and their `ios.rs` included (`design/connection/network.md`). Releases are the exception on Android only: `.github/workflows/release.yml` builds and signs the APK on a `v*` tag or by hand, and iOS is built and uploaded from a Mac (`design/releases.md`).
- **Steps, in order**:
  1. `rustup toolchain install`, which reads `rust-toolchain.toml`.
  2. `apt-get install` of `libwebkit2gtk-4.1-dev`, `libsoup-3.0-dev`, `libjavascriptcoregtk-4.1-dev`, `libssl-dev`, `libxdo-dev`, `libayatana-appindicator3-dev` and `librsvg2-dev`: Tauri 2's prerequisites for Debian and Ubuntu.
  3. `Swatinem/rust-cache` for `target/` and cargo's registry.
  4. pnpm, at the version of `packageManager`, and Node 22 with pnpm's store cached.
  5. `pnpm install --frozen-lockfile`, then `pnpm build`.
  6. `cargo fmt --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`.
  7. `pnpm check` (svelte-check on `src/` and `site/src/`, then `tsc -p tsconfig.node.json` on `vite.config.ts`, which svelte-check leaves out), `pnpm lint` (ESLint, then `scripts/check-rules.mjs`), `npx -y jscpd@4.3.0`, `pnpm test`.
- **Clippy and the tests cover the whole workspace**, `src-tauri` included, built for Linux desktop. That is why the job installs WebKitGTK and its friends. Rejected: excluding `src-tauri` to skip them, which would leave the shell unchecked.
- **`pnpm build` runs before cargo**: `tauri::generate_context!` embeds `dist/` (`frontendDist`) when Tauri builds with `custom-protocol`, as `tauri build` and `tauri ios build` do, and fails without it. A dev build, which is what clippy and the tests compile, does not need it (checked on 2026-11-08 with Tauri 2.12.5). The step still goes first, so that CI proves the frontend bundles and cargo stays green if a check ever enables `custom-protocol`.
- **The Rust cache is saved from `main` only**, as in cornercase-terminal: pull requests restore `main`'s cache and do not fill the repository's quota with caches no other branch can read. The first pull request builds everything from scratch.
- **pnpm 12 refuses a package published less than a day ago** (`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`), even with `--frozen-lockfile`. A Dependabot pull request that bumps something that new fails until the day has passed; rerun the job then.
- **Checked live**: the steps from `pnpm install` on, from a clean tree on macOS, on 2026-11-08. The apt packages are only checked by the job itself.
- **Dependabot** (`.github/dependabot.yml`): cargo, npm and GitHub Actions, monthly, one grouped pull request per ecosystem, titled `chore(deps): …`. It ignores TypeScript majors (see Architecture).
